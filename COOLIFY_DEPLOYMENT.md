# Coolify deployment

This repository is a full-stack application:

- Vite/React frontend
- Express API under `/api`
- PostgreSQL through Prisma
- Persistent user uploads

The root `Dockerfile` builds both applications and serves them from one container and one domain. Do not deploy this repository with Coolify's Static build pack.

## 1. Create PostgreSQL

In the same Coolify project and environment, create a PostgreSQL resource. Keep it private. Copy the internal connection URL shown by Coolify.

## 2. Configure the GitHub application

Use the existing GitHub App source, then set:

- Build Pack: `Dockerfile`
- Base Directory: `/`
- Dockerfile Location: `/Dockerfile`
- Port Exposes: `47831`
- Health Check Path: `/api/health`
- Health Check Expected Status: `200`

Do not enable Coolify's “Static site” option.

## 3. Runtime environment variables

Add these in Coolify's Environment Variables section:

```env
DATABASE_URL=postgresql://USER:PASSWORD@INTERNAL_POSTGRES_HOST:5432/DATABASE?schema=public
NODE_ENV=production
PORT=47831
UPLOAD_DIR=/app/data/uploads
```

Use the exact internal PostgreSQL URL generated by Coolify. `DATABASE_URL` is a runtime secret and does not need to be enabled as a build variable.

The container runs `prisma migrate deploy` before starting the web server, so committed migrations are applied automatically on deployment.

## 4. Persistent uploads

In the application's Persistent Storage settings, add a volume:

- Name: `halal-program-uploads`
- Destination Path: `/app/data/uploads`

Without this volume, uploaded seals, supporting documents, and logos are lost whenever Coolify replaces the container.

## 5. Deploy and verify

After deployment, open:

```text
https://YOUR-DOMAIN/api/health
```

The expected response includes:

```json
{"ok":true,"database":"connected","fallback":false}
```

If it returns HTTP `503` with `database: "offline"`, the application container cannot reach `DATABASE_URL`. Confirm the application and PostgreSQL resource share a network, and that the URL uses Coolify's internal database hostname.

Then submit one test form and confirm it appears in the dashboard before accepting production traffic.
